# ThinQ Web Accessibility Checker 프로젝트 행동 규칙

1. 소스 코드 수정 전에 반드시 구체적인 원인 분석과 개선 방안을 문서로 작성하여 보고하고, 사용자의 리뷰 및 최종 승인을 받아야 합니다.
2. 사용자의 명시적인 승인 없이 임의로 코드를 수정하거나, Terminal 명령어를 실행하거나, Git Commit/Push를 수행해서는 안 됩니다.
3. 모든 작업 시 side effect(기존 기능 퇴화)가 발생하지 않도록 철저히 검증하고 관련 Unit Test를 동반하여 추가해야 합니다.
4. 질문에 대해 정확하지 않은 대답은 하지 않고 데이터를 확인하고 대답한다.
5. 기능 설계 및 수정시 브라우저의 제약이 없는지 확인한다.
6. 모든 원인 분석 및 코드 수정 시 짐작이나 추정이 아닌, 제공된 실제 로그 파일의 원본 데이터(접근성 이름, 속성명 등)를 대조·확인하여 정확한 원인을 진단하며, 해당 실제 데이터 패턴을 모방한 단위 테스트(Unit Test)를 필수로 추가하여 검증한다.
7. 상태 지시자/스위치(switch-toggle, static text) 제외 규칙 등 크롤링 후보 필터링을 구현할 때, 자식/후손 노드의 상태 텍스트 패턴이 전파되어 부모의 정상적인 대화형 요소(`button`, `a`, `role="button/link/tab"`)까지 스킵을 유발하지 않도록, 강한 인터랙티브 요소는 직접적인 스위치/체크박스/라디오 컨트롤이 아닌 한 제외 처리에서 기본 면제(bypass)되도록 방어 코드를 설계하고, 이에 대한 단위 테스트를 필수로 추가하여 검증해야 합니다.
